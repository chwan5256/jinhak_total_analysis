# 생기부 렌즈 · Record Lens

> `jinhak_total_analysis` · 만든이 **남강고등학교 진로진학부** · © 2026

학생부종합전형 **서류평가에서 이 생활기록부가 어떻게 읽힐지**를 진단하는 교사용 도구입니다.

학종은 **서류 100%** 또는 **서류 + 면접**으로 뽑고, 서류 평가요소(학업역량·진로역량·공동체역량 등)의 **비중은 대학마다 다릅니다.** 진로역량 50%인 전형과 학업역량 50%인 전형에서 같은 학생부가 전혀 다르게 읽힙니다.
이 도구는 생활기록부를 문장 단위로 **분해**하고, 여러 영역에 흩어진 활동의 핵심요소를 **연결**한 뒤, 지원하려는 대학·전형의 **실제 평가요소 비중에 맞춰 대조**합니다. 그 대학이 크게 보는 요소에 근거가 두꺼운지 얇은지를 드러내 **교사가 서류 경쟁력을 직접 판단**할 재료를 만듭니다.

- 단일 HTML 파일 · 무빌드 · 서버 없음 · 데이터베이스 없음 · 저장 기능 없음
- 업로드한 생기부는 외부로 전송되지 않으며, 새로고침하면 즉시 소멸합니다
- GitHub Pages로 배포되어 교실 PC·태블릿 어디서나 URL 하나로 열립니다

**이 도구가 하지 않는 것** — 합격을 예측하지 않고, 지원 여부를 판단하지 않으며, 학생을 평가하지 않습니다. 상담 전에 읽어야 할 것을 정리할 뿐이고 최종 판단은 교사가 합니다.

| 산출 | 학년별 위계성 진단 · 전공 이수 점검표 · 상담 요약 시트 · CSV · 엑셀 · PDF · 인쇄 · 메일 |

## 평가요소 체계

2022년 5개 대학 공동연구 기준 학생부종합전형 공통 평가요소를 그대로 따릅니다.

- **학업역량** — 학업성취도 / 학업태도(자기주도) / 탐구력
- **진로역량** — 전공 관련 교과 이수 노력 / 전공 관련 교과 성취도 / 진로 탐색 활동과 경험
- **공동체역량** — 협업과 소통능력 / 나눔과 배려 / 성실성과 규칙준수 / 리더십

## 신뢰도를 표시하는 이유

자동 분류는 보조 도구일 뿐이며, 학업역량과 진로역량의 경계에 놓인 문장(교과 개념을 전공 대상에 적용한 세특 등)은 원리적으로 한쪽으로 확정할 수 없습니다.
그래서 이 도구는 **판단을 숨기지 않고 신뢰도로 드러냅니다.** 신뢰도 60% 미만 문장은 노란 점선 테두리로 표시되며, 툴바의 "재검토 필요만 보기"로 모아 볼 수 있습니다. 최종 판단은 교사가 합니다.

## 개발

```bash
# 로컬에서 열기 (file:// 로 열어도 동작하지만, OCR·PDF 워커는 http 권장)
python3 -m http.server 8000
# http://localhost:8000
```

버전 올리고 배포까지 한 번에:

```powershell
# Windows (PowerShell)
.\scripts\release.ps1 "드래그 UX 개선"                # 패치 버전 +1
.\scripts\release.ps1 "분류 로직 전면 개편" -Minor      # 마이너 버전 +1
.\scripts\release.ps1 "오타 수정" -NoBump             # 버전 유지
```

```bash
# macOS / Linux / Git Bash
./scripts/release.sh "드래그 UX 개선"
./scripts/release.sh -m "분류 로직 전면 개편"
./scripts/release.sh -n "오타 수정"
```

`main`에 푸시되면 GitHub Actions가 인라인 스크립트 문법 검사 → 단일 파일 원칙 검사 → 버전 표기 일치 검사를 거쳐 Pages에 배포합니다.

## 코드 구조

단일 파일이지만 내부는 레이어로 나뉘어 있습니다. 기능을 추가할 때는 해당 레이어만 건드리면 됩니다.

```
CONST     TAXONOMY / RULES / SECTION_PRIOR / MAJORS
STATE     state 객체 하나로 단일화 (전역 변수 없음)
Parse     reflowTextContent · reflow · segment · splitSentences
Classify  run(text, section) → {cat, sub, conf}
Stats     compute() → byCat / bySub / byGrade / lowConf
Render    summary · gradeFlow · table · consulting · counselSheet · majorDiagnostic
Export    csv · sheetText · copySheet
UI        dialog · progress · handlePdf · runOcr · move/cycle/undo · init
```

전공을 추가하려면 `MAJORS`에 항목 하나를 넣으면 셀렉트 박스·점검표·면접 질문이 자동으로 따라옵니다.
다만 **학과 표준은 `index.html` 이 아니라 `data/majors.json` 에 있습니다.** 현재 6개 계열 42개 학과군입니다.

```
data/majors.json          학과 표준 원본 — 여기만 고칩니다
scripts/build_majors.py   검증 + index.html 시드 재생성
index.html                MAJORS_SEED(계열 대표 6개) — 자동 생성 구역, 손대지 않습니다
```

학과를 추가하려면 `rows` 에 항목 하나를 넣고 `python scripts/build_majors.py` 를 실행한 뒤, `data/majors.json` 과 `index.html` 을 함께 커밋합니다. `group` 값은 `groups` 배열(공학 / 자연과학 / 의약·보건 / 사회과학 / 인문·어문 / 사범·교육) 중 하나여야 계열 묶음에 들어갑니다.

`file://` 로 직접 열면 브라우저가 CORS로 JSON을 막습니다. 그때는 계열 대표 6개 축약본으로 동작하며, 화면 상단에 그 사실이 표시됩니다. 전체 학과군을 보려면 배포된 주소로 접속하십시오.
분류 규칙을 조정하려면 `RULES`의 가중치(3.0 결정적 / 1.8 강함 / 1.0 보통)만 손보면 됩니다.

## 외부 의존성

CDN에서 스크립트로만 불러오며 번들링하지 않습니다. 학교망에서 CDN이 차단되어도 페이지 자체는 죽지 않도록 방어 코드가 들어 있습니다.

| 라이브러리 | 용도 |
|---|---|
| Tailwind CSS (play CDN) | 스타일 |
| pdf.js 3.11.174 | PDF 텍스트 레이어 추출, 한글 CMap |
| Tesseract.js 5 | 스캔본 OCR 폴백 |
| Font Awesome 6 | 아이콘 |

> pdf.js의 한글 CMap과 Tesseract의 언어 데이터는 런타임에 CDN에서 **fetch**로 받아옵니다. 스크립트 외 리소스 fetch를 막는 환경(예: 일부 샌드박스 호스팅)에서는 PDF 한글 추출과 OCR이 동작하지 않습니다. GitHub Pages에는 그런 제약이 없습니다.

공시 자료가 없는 대학은 비슷한 수준 대학의 기준으로 대신 보여주고 그 사실을 화면에 적습니다.
**최종 확인은 반드시 해당 대학 2027 수시모집요강으로 하십시오.**

## 면접 자료의 출처와 범위

문항은 각 대학이 법정 공시하는 **선행학습 영향평가 자체평가 보고서**에서 추출한 실제 출제 문항입니다. 생성한 문항이 아닙니다.

- **범위**: 학생부종합전형만. 논술 기출은 추출 단계에서 제외합니다. 학종은 서류 100%와 서류+면접으로 나뉘므로 문항마다 전형 유형을 표기합니다.
- **출처 표기**: 문항마다 어느 대학 기출인지 적습니다. 지원 대학의 자료가 없으면 비슷한 수준의 다른 대학 기출로 대신 보여주고 그 사실을 밝힙니다.
- **공통 문항**: 자기소개·지원동기·활동 확인은 대학을 가리지 않으므로 별도로 제공합니다.

| 군 | 대학 |
|---|---|
| 1군 | 연세대 고려대 서강대 한양대 성균관대 중앙대 경희대 서울시립대 건국대 홍익대 |
| 2군 | 국민대 서울과기대 숭실대 동국대 세종대 광운대 한국항공대 인하대 아주대 단국대 인천대 |
| 3군 | 한성대 삼육대 서경대 명지대 상명대 수원대 가톨릭대 경기대 가천대 한국공학대 |

공개 범위는 대학마다 다릅니다. **자료가 없는 군은 없는 대로 넘어갑니다** — 선택지에 "자료 없음"으로 표시하고 빈 화면 대신 그 사실을 적습니다. 현재 수록은 2군(동국대) 44문항입니다.

## 답안 초안은 주되, 모범답안은 아닌 이유

외운 답은 꼬리 질문에서 무너지고, 면접관이 확인하는 것은 학생부에 적힌 **본인의 경험**입니다.

그래서 자기소개·지원동기 초안은 **이 학생의 생기부 문장만** 골라 1인칭으로 기계 변환해 조립합니다. 없는 경험은 만들어 넣지 않으므로, 기록이 얇으면 초안도 목표 분량에 미치지 못하고 화면이 그 사실을 그대로 적습니다. 문장 끝의 `[n]`은 출처이며, 하단 목록에서 `3학년 · 세특 · 물리학Ⅱ — "원문…"` 형태로 확인할 수 있습니다. 출처가 없는 문장은 연결을 위한 구성 문장입니다.

어미 변환은 기계적이라 어색한 문장이 섞입니다. **학생 본인의 말로 다시 쓰는 것을 전제로 한 뼈대**이지, 외울 답이 아닙니다. 나머지 문항은 여전히 답 대신 답변 설계 틀(상황–행동–결과–성찰)과 그 질문에 쓸 근거의 위치를 보여줍니다.

같은 이유로 이 앱에는 **AI API 키가 없습니다.** 공개 웹페이지에 키를 두면 키가 노출되고 학생 자료가 외부로 나갑니다. 첫 번째 원칙(학생 자료는 브라우저를 떠나지 않는다)과 양립할 수 없습니다.

## 인쇄 · 저장 범위

인쇄와 PDF 저장은 **결과 부분만** 담습니다. 헤더·푸터·업로드 화면·액션바·필터·모달·토스트·부록은 전부 제외되고, 인쇄 전용 머리글(학생·문장 수·출력일·원본 파일명)과 꼬리말(만든이)이 붙습니다. PDF는 인쇄 창의 '대상 → PDF로 저장'을 쓰므로 인쇄와 완전히 같은 범위입니다.

## 개인정보 처리

서버로 올리지 않고, 데이터베이스에 넣지 않으며, 어디에도 저장하지 않습니다. 저장 기능을 일부러 만들지 않았습니다. 외부로 나가는 요청은 화면을 그리는 라이브러리(Tailwind·pdf.js·Tesseract·아이콘) 뿐이고 학생 자료가 그 요청에 실리지 않습니다.

내려받은 CSV·엑셀·PDF에는 **학생 실명이 들어갑니다.** 개인 클라우드나 메신저로 옮기지 마시고, 공용 PC에서는 사용 후 브라우저를 닫으시고, 출력물은 학교 규정에 따라 관리하십시오.
